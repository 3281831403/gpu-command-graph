# GPU 命令图 / 帧图编译器（Bugfix）

## ① 题面

换成帧图后，偶尔读到上一帧的内容、显存别名还写出了花屏：现有编译器把 pass 注册顺序当成拓扑序，完全忽略 reads/writes 数据依赖；屏障只在写之后插入，读后不插，read→write 冒险挡不住；同一资源连续两次读也各插一道屏障，屏障数量虚高；别名分配只按生命周期区间是否重叠判断，不比较资源读写态，含读资源在末次写之后就被释放并复用，读写别名冲突；pool_size 不校验，别名后总大小越过显存池仍返回布局；死代码消除只删无输入的 pass，未使用输出的 pass 继续留在图里；derive_state 把同一资源的读+写推导成读，状态机从源头就错；validate_graph 不检测依赖环，非法图被接受；compile_batch 复用上一张图的资源状态表，第二张图从第一张图的末尾状态开始；add_pass 遇到未注册的写资源时静默建表，拼写错误的资源被当成新资源。难点是状态机：资源读写态 → 屏障 → 别名生命周期，三者必须一致。fg/graph.py 是核心，tests/test_graph.py 15个红。要修的是：按 reads/writes 建依赖并稳定拓扑排序；按资源读/写/读写态插入最少屏障；把读访问纳入别名生命周期并守住 pool_size；按“被使用输出”反向裁剪；正确推导读、写、读写；检测环并报告环节点；每张图使用独立的资源状态；拒绝未注册资源。

## ② 运行方式与初始状态

在仓库根目录执行：

```bash
python -m pytest tests -q
```

初始预期是恰好 15 个失败，且没有 collection error、import error 或 syntax error：

```text
15 failed in 0.09s
```

退出码为 1 是正常的：8 个公开函数都还是 `raise NotImplementedError` 的桩，15 个测试会分别红。不要通过修改或跳过 tests 来改变这个结果。
